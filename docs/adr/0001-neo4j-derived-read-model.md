# 0001. Neo4j — производная read-only витрина, мастер-системы остаются system of record

- **Статус:** Принято
- **Дата:** 2026-10-03
- **Источник:** [`00-vision.md`, «Резюме решения»](../00-vision.md#резюме-решения); [`00-vision.md`, «Целевая архитектура»](../00-vision.md#целевая-архитектура)
- **Кто принял:** архитектор, принято владельцем

## Контекст

Архитектурные активы живут в нескольких мастер-системах (EAM, SCM, asset DB, deploy map). Агентам нужен единый граф связей между ними, но ни одна система не должна терять статус владельца данных.

## Решение

Neo4j хранит производную витрину, которую можно перестроить из raw storage. Источником истины остаются мастер-системы. Запись в граф выполняет только projector, агенты граф читают. Правки руками в графе не делаются: ошибочное состояние исправляется повторной проекцией.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Neo4j — производная read-only витрина | Мастера не затрагиваются, граф перестраивается replay-ем | Нужны синхронизация и контроль актуальности | Выбран |
| Neo4j как новый system of record | Один источник для связей | Дублирует мастеров, появляется конфликт владения | Отклонён: мастера остаются владельцами |
| Федеративные запросы к мастерам без графа | Нет копии данных | Нет обходов по связям, нагрузка на источники | Отклонён |

## Последствия

- **Положительные:** Rebuild из raw storage даёт тот же граф (критерий 4). Ошибки источника не становятся постоянными.
- **Отрицательные / ограничения:** Данные в графе отстают от мастеров на время синхронизации; нужны freshness и reconciliation.
- **Затронутый код:** `ingestion/*`, `access/*`
