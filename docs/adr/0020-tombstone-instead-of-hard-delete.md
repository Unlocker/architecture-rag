# 0020. Tombstone вместо hard delete; удаления из snapshot — только после `snapshot-complete`

- **Статус:** Принято
- **Дата:** 2026-10-03
- **Источник:** [`00-vision.md`, «Синхронизация»](../00-vision.md#синхронизация); [`00-vision.md`, «Identity resolution»](../00-vision.md#identity-resolution); UNLOCKER-168; UNLOCKER-169
- **Кто принял:** архитектор, принято владельцем

## Контекст

Падение на середине загрузки может ошибочно удалить половину витрины. Узел может подтверждаться несколькими системами.

## Решение

Удаление ставит tombstone на `SourceRecord`. Канонический узел закрывается только при отсутствии других активных assertions. Missing set вычисляется только после маркера `snapshot-complete`. High-water mark двигается после успешной проекции страницы.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Tombstone + ожидание `snapshot-complete` | Нет потери данных при сбое | Хранятся неактивные записи | Выбран |
| Hard delete по отсутствию в загрузке | Проще | Риск потери витрины | Отклонён |

## Последствия

- **Положительные:** Предсказуемое поведение при сбоях источника.
- **Отрицательные / ограничения:** Нужна политика архивации.
- **Затронутый код:** `ingestion/graph-projector`, `ingestion/*` (reconciliation)
