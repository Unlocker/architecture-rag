# 0003. Каноническая идентичность: `gid: UUID` и `SourceRecord {source, sourceType, sourceId}`

- **Статус:** Принято
- **Дата:** 2026-10-03
- **Источник:** владелец 2026-10-03 (решение 5); UNLOCKER-159; [`00-vision.md`, «Идентичность узлов»](../00-vision.md#идентичность-узлов)
- **Кто принял:** владелец

## Контекст

Один актив подтверждается несколькими системами. Универсальный `externalId` на узле смешивает источник с бизнес-сущностью и не даёт точки для версии, hash и tombstone. В исходном видении ключом `SourceRecord` было поле `key`.

## Решение

На всех канонических узлах хранится внутренний `gid: UUID`. Внешняя идентичность — отдельные узлы `SourceRecord`, уникальные по `(source, sourceType, sourceId)`, связанные с узлом через `ASSERTS`. Поле `key` заменено на `source`.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| `gid` + `SourceRecord`, поле `source` | Несколько источников у одного узла, tombstone, версия и hash | Дополнительные узлы и связи | Выбран |
| `SourceRecord` с полем `key` (прежний вариант) | Короткое имя | Двусмысленное имя; владелец заменил на `source` | Заменён решением владельца |
| Один `externalId` на узле | Просто | Нельзя подтвердить актив несколькими системами | Отклонён |

## Последствия

- **Положительные:** Аудит конфликтов и rebuild опираются на `SourceRecord`.
- **Отрицательные / ограничения:** Формат `sourceId` не зафиксирован: см. ADR [0024](0024-open-source-id-format.md).
- **Затронутый код:** `contracts/canonical-model/...`, `ingestion/graph-projector/.../schema/Neo4jSchema.java`
