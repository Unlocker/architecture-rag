# 0011. `Namespace` и `KubernetesCluster` моделируются, но не наполняются

- **Статус:** Принято
- **Дата:** 2026-10-03
- **Источник:** владелец 2026-10-03 (решение 6); [`00-vision.md`, «Основные узлы»](../00-vision.md#основные-узлы)
- **Кто принял:** владелец

## Контекст

Вертикальный срез PoC: `ITSystem → Service → Deployment → Environment → ComputeInstance`. Kubernetes-сущности в срез не входят, но тип нужен для целевой модели.

## Решение

Типы `Namespace` и `KubernetesCluster` описаны в модели и схеме, но ни один адаптер их не заполняет.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Моделировать, не наполнять | Модель не придётся менять позже | Неиспользуемые типы | Выбран |
| Не моделировать | Меньше кода | Миграция модели позже | Отклонён |
| Наполнять в PoC | Полнее | Нет источника, расширяет объём | Отклонён |

## Последствия

- **Положительные:** `find_runtime_footprint` в PoC не возвращает кластеры и namespace.
- **Отрицательные / ограничения:** Типы без данных не покрыты интеграционными тестами.
- **Затронутый код:** `contracts/canonical-model/...`
