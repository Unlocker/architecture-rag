# 0007. Raw storage — S3-совместимое хранилище; SeaweedFS вместо MinIO в тестах и на стенде

- **Статус:** Принято
- **Дата:** 2026-10-04
- **Источник:** UNLOCKER-202 (2026-10-04); [PR #7](https://github.com/Unlocker/architecture-rag/pull/7)
- **Кто принял:** владелец

## Контекст

Raw payload нужен для rebuild и replay. Изначально в тестах и на стенде использовался MinIO, но MinIO больше не публикует образы.

## Решение

Raw payload хранится в S3-совместимом хранилище; код работает по S3 API, а не по продукту. В тестах (Testcontainers) и на демо-стенде используется SeaweedFS.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| SeaweedFS | S3 API, публикуемые образы | Совместимость S3-клиента с SeaweedFS нужно проверять в `*IT` | Выбран |
| MinIO (прежний вариант) | Знаком, S3 API | Образы больше не публикуются | Заменён |
| Хранить payload в PostgreSQL | Одно хранилище | Рост БД, нет S3-границы для production | Отклонён |

## Последствия

- **Положительные:** Код не привязан к продукту S3.
- **Отрицательные / ограничения:** Нужно проверять совместимость S3-клиента с SeaweedFS в `*IT`.
- **Затронутый код:** `platform/integration-tests`, `ingestion/*`
