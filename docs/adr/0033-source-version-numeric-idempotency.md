# 0033. Версия источника — неотрицательное целое; идемпотентность по сравнению через `BigInteger`

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Источник:** UNLOCKER-278; кандидат К-1 в `_reversa_sdd/adrs/candidates.md` (UNLOCKER-269); согласие владельца с рекомендациями архитектора в UNLOCKER-260 (2026-10-13); реализация — UNLOCKER-168, UNLOCKER-175
- **Кто принял:** владелец, 2026-10-13

## Контекст

ADR [0006](0006-postgres-inbox-event-backbone.md) и [0020](0020-tombstone-instead-of-hard-delete.md) требуют идемпотентной обработки, а ADR [0008](0008-authority-matrix-field-level.md) отвергает last-write-wins по времени. Правило сравнения версий источника в реестре не было зафиксировано, хотя от него зависят статусы `DUPLICATE` и `IGNORED_OLD_VERSION`, воскрешение удалённых записей и порядок параллельных проекций.

## Решение

1. **Формат версии.** `SourceVersion` — строка из 1–40 десятичных цифр (неотрицательное целое). Нечисловая версия отклоняется при создании значения (`IllegalArgumentException`) и не доходит до сравнения (`contracts/event-schemas/.../SourceVersion.java:11-17`).
2. **Сравнение — числовое, через `BigInteger`**, а не лексикографическое: `99` младше `184` (`SourceVersion.java:19-22`).
3. **Исходы** (`VersionDecision`, `ingestion/graph-projector/.../VersionDecision.java:13-38`):
   - запись ещё не применялась или версия выше применённой — `APPLY`;
   - версия равна — `SAME`: повтор того же изменения под другим `eventId` (например, webhook и polling), не ошибка; событие получает статус `DUPLICATE` (`EventProcessor.java:319`), в проекции — `NOOP_SAME_VERSION` (`GraphProjector.java:321-322`);
   - версия ниже — `OLD`: статус `IGNORED_OLD_VERSION`, граф не меняется.
4. **Tombstone с равной версией** применяется, если применённая запись ещё активна: удаление не обязано повышать версию объекта. Для уже неактивной записи равная версия — `SAME` (`VersionDecision.java:30-38`). Следствие: upsert той же версии, что у tombstone, удалённую запись не воскрешает.
5. **Двойная проверка.**
   - До записи, пока событие `RECEIVED`: `EventProcessor.decideBeforeWrite` (`EventProcessor.java:302-321`); для `RETRYING` старая версия отсекается до записи в PostgreSQL (`ignoreIfOlderOnRetry`, `EventProcessor.java:323-344`), иначе устаревшие утверждения затёрли бы свежие.
   - В транзакции Neo4j после блокировки записи: `MERGE (r:SourceRecord …) SET r._lock = true REMOVE r._lock`, затем чтение версии и повторное решение (`GraphProjector.java:302-324`). Это защищает от обгона при параллельных проекциях одного объекта.
6. **Требование к источникам.** Новый источник обязан отдавать монотонную числовую версию объекта. Источник без такой версии (хеши, ISO-строки, семвер) подключать нельзя без отдельного решения архитектора.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| A. Числовая версия, сравнение `BigInteger` | Однозначный порядок, нет зависимости от часов источников | Источник обязан иметь монотонное целое | Выбран |
| B. Лексикографическое сравнение строк | Принимает любые версии | `99` > `184`, неверный порядок | Отклонён явно (Javadoc `SourceVersion`) |
| C. Last-write-wins по времени | Не требует версии | Зависит от часов, ломает идемпотентность | Отклонён ADR [0008](0008-authority-matrix-field-level.md) |

## Последствия

- **Положительные:** повтор и устаревшее событие не меняют граф; tombstone и upsert одной версии не конфликтуют; параллельные проекции не обгоняют друг друга.
- **Отрицательные / ограничения:** источник без монотонной числовой версии не подключается; версия длиннее 40 цифр отклоняется; версия tombstone, который создаёт `Reconciler`, берётся из применённой записи ([ADR 0035](0035-reconcile-tombstone-via-journal.md)).
- **Затронутый код:** `contracts/event-schemas` (`SourceVersion`), `ingestion/graph-projector` (`VersionDecision`, `EventProcessor`, `GraphProjector`).
