# 0012. `analyze_impact` — режим `trace_dependencies(mode=impact)`, а не отдельный tool

- **Статус:** Принято
- **Дата:** 2026-10-03
- **Источник:** владелец 2026-10-03 (решение 7); UNLOCKER-188; [`00-vision.md`, «Tools первого релиза»](../00-vision.md#tools-первого-релиза)
- **Кто принял:** владелец

## Контекст

Исходно видение предлагало отдельный tool `analyze_impact`. Impact — тот же обход зависимостей, только в обратную сторону и с другим форматом ответа.

## Решение

Один tool `trace_dependencies` с параметром `mode` (`trace` | `impact`). `trace` возвращает ограниченный subgraph/path, `impact` — зависимые системы и сервисы с объяснимыми путями, provenance и freshness.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Режим `impact` в `trace_dependencies` | Меньше tools, общий traversal и лимиты | Параметр меняет форму ответа | Выбран |
| Отдельный `analyze_impact` (прежний вариант) | Явная семантика | Дублирует обход и лимиты | Заменён |

## Последствия

- **Положительные:** Один набор лимитов глубины.
- **Отрицательные / ограничения:** Схема ответа зависит от `mode`.
- **Затронутый код:** `access/graph-query-core`, `access/mcp-server`
