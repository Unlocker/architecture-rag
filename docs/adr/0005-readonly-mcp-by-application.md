# 0005. Read-only MCP обеспечивается приложением: `executeRead` и раздельные учётные данные

- **Статус:** Принято
- **Дата:** 2026-10-03
- **Источник:** UNLOCKER-176; владелец 2026-10-03 (решение 4); [`00-vision.md`, «Безопасность»](../00-vision.md#безопасность); [`00-vision.md`, «Критерии готовности PoC»](../00-vision.md#критерии-готовности-poc) (п. 6)
- **Кто принял:** владелец по предложению архитектора

## Контекст

В Community нет ролей, поэтому БД не запретит запись из MCP-сервиса. Критерий готовности 6 требует, чтобы MCP не мог выполнить write query.

## Решение

`graph-query-core` использует только `session.executeRead(...)` и не содержит write-шаблонов. У `mcp-reader` и `graph-projector` раздельные учётные записи и секреты, writer-учётные данные недоступны MCP-сервису. Запрет записи на уровне БД перенесён в production gap list (роли Enterprise).

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Запрет в приложении + раздельные учётные данные | Работает в Community | Защита зависит от кода | Выбран |
| Роли Neo4j (reader/writer) | Запрет на уровне БД | Только Enterprise | Отклонён для PoC; production gap list |
| Разбор Cypher на лету (`EXPLAIN`) | Гибкость | Можно обойти кастомными процедурами | Отклонён |

## Последствия

- **Положительные:** Негативные тесты доказывают отсутствие write-пути.
- **Отрицательные / ограничения:** Нужен ревью-контроль: любой write-шаблон в `graph-query-core` — дефект.
- **Затронутый код:** `access/graph-query-core`, `access/mcp-server`
