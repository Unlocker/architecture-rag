# 0014. SLA webhook → Neo4j: p95 ≤ 30 с на заглушках

- **Статус:** Принято
- **Дата:** 2026-10-03
- **Источник:** решение архитектора, принятое владельцем (решение 9); UNLOCKER-171; [`00-vision.md`, «Критерии готовности PoC»](../00-vision.md#критерии-готовности-poc) (п. 2)
- **Кто принял:** владелец по предложению архитектора

## Контекст

Критерий готовности 2 не задавал число. Для приёмки нужна проверяемая граница.

## Решение

p95 времени от webhook до появления изменения в Neo4j не больше 30 с на заглушках. Замер выполняется в приёмке E1 (UNLOCKER-171).

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| p95 ≤ 30 с | Измеримо, достаточно для PoC | Не гарантия для реальных систем | Выбран |
| Без числа | — | Неприемлемо для приёмки | Отклонён |

## Последствия

- **Положительные:** Есть цель для замеров sync lag.
- **Отрицательные / ограничения:** Для реальных источников SLA нужно пересматривать.
- **Затронутый код:** `platform/integration-tests`
