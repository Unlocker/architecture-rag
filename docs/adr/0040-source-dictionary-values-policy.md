# 0040. Единая политика словарных значений источника: необязательное поле — предупреждение, ключевое — карантин

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Источник:** UNLOCKER-278; кандидат К-10 в `_reversa_sdd/adrs/candidates.md` (UNLOCKER-269); согласие владельца в UNLOCKER-260 (2026-10-13); реализация — UNLOCKER-256, UNLOCKER-287
- **Кто принял:** владелец, 2026-10-13

## Контекст

Значение словаря источника вне ожидаемого набора (например, `criticality` EAM не из `HIGH|MEDIUM|LOW`) нормализатор обрабатывает по-разному: где-то событие применяется с предупреждением, где-то уходит в карантин. Политика нигде не оформлена, для новых источников выбор пришлось бы делать заново.

## Решение

Значения словаря не угадываются и не отображаются «по похожести». Единая политика:

1. **Необязательное поле** с неизвестным значением: каноническое поле остаётся `null`, сырое значение сохраняется в отдельном свойстве, в журнал уходит только код предупреждения, событие применяется.
2. **Ключевое или обязательное поле** с неизвестным значением: `QUARANTINED` с кодом `INVALID_PAYLOAD`; причина называет поле, но не значение (значения источника недоверенные).

Как в коде сейчас:

- `criticality` у `IT_SYSTEM` в EAM следует политике: значение вне таблицы даёт `null`, сырое значение сохраняется, код `UNMAPPED_CRITICALITY`, событие применяется (`ingestion/normalizer/.../EamMapper.java:189-202`, `:144-158`); счётчик `archrag.normalizer.unmapped.values` с тегами `source`, `property` (`ingestion/ingestion-service/.../IngestionMetrics.java:53`, `:58`, `:134`).
- Неизвестное значение обязательного поля уходит в карантин: например `kind` в CMDB, обязательный (`CmdbMapper.java:36-37`, `:55`).

Расхождение закрыто в UNLOCKER-287: необязательный `criticality` в старом формате `IT_SYSTEM` (без `attrs`) и у `SERVICE_DEPENDENCY` с неизвестным значением больше не бросает `INVALID_PAYLOAD`. Каноническое поле остаётся `null`, сырое значение уходит в `criticalityRaw`, код `UNMAPPED_CRITICALITY` (`EamMapper.java:77-89`, `:109-117`, `:134-154`).

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| A. Предупреждение для необязательных, карантин для ключевых и обязательных | Новое значение словаря не блокирует приём; ключи не искажаются | Нужно различать роль поля в каждом маппере | Выбран |
| B. Всегда карантин | Строго | Один новый справочный код блокирует запись целиком | Отклонён |
| C. Приведение «по похожести» | Меньше `null` | Тихо искажает данные | Отклонён |

## Последствия

- **Положительные:** предсказуемое поведение для новых источников; сырое значение доступно для разбора без потери.
- **Отрицательные / ограничения:** каждый новый словарь требует явной классификации поля.
- **Затронутый код:** `ingestion/normalizer` (`EamMapper`, `CmdbMapper`), `ingestion/ingestion-service` (`IngestionMetrics`).
