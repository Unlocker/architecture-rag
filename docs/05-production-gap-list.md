# Production gap list (критерий готовности 10)

Что отделяет демо-стенд PoC на Docker Compose от production. Документ не повторяет то, что уже записано:

- таблица PoC/Production и «Production delta» — в [`00-vision.md`](00-vision.md) (разделы «Решения владельца для PoC», «PoC topology», «Безопасность»);
- допущения стенда (самоподписанный CA, `bolt+ssc`, секреты в `environment` у образов без `_FILE`, сети `edge`) — в [`platform/docker/README.md`](../platform/docker/README.md), раздел «Допущения демо и gap list»;
- замеры, на которые опираются оценки, — в [`04-poc-measurements.md`](04-poc-measurements.md).

Здесь для каждого пункта: **риск** при переносе PoC в production «как есть», **целевое решение** и грубая **оценка трудозатрат** (S — дни, M — 1–3 недели, L — месяц и более; оценка команды из двух разработчиков, без согласований и закупок).

## 1. Платформа и данные

| # | Пробел | Риск | Целевое решение | Оценка |
|---|---|---|---|---|
| 1.1 | Docker Compose на одном хосте вместо Kubernetes | Нет отказоустойчивости хоста, rolling update, автоперезапуска по readiness, `NetworkPolicy` | Helm-чарты сервисов (`mcp-server` ≥ 2 реплики, `ingestion`, адаптеры), `Ingress`/gateway, PVC, секреты через External Secrets/Vault; reconciliation как `CronJob` вместо планировщика внутри адаптера | L |
| 1.2 | Neo4j Community, один сервер | Отказ узла = простой всего графа и MCP; восстановление только из `dump` с остановкой сервиса (≈ минуты простоя на каждый backup, см. README, «Backup и restore») | Neo4j Enterprise: кластер минимум из 3 серверов, лицензия, online backup (`neo4j-admin backup`) на постоянное хранилище. Лицензия — решение владельца | L |
| 1.3 | Read-only и разделение reader/writer обеспечивает приложение (`executeRead` и раздельные пароли), ролей нет | Ошибка в шаблоне запроса или компрометация процесса `mcp-server` не ограничена на уровне БД; нет аудита на стороне Neo4j | Enterprise RBAC: роли `projector-writer`, `mcp-reader`, `operator`; `DENY` на запись для reader. Негативные тесты уровня БД. Domain-фильтрацию по свойству (PBAC) всё равно дублировать в query-слое (vision, «Безопасность») | M |
| 1.4 | Event backbone — PostgreSQL inbox (вариант A) | Пропускная способность и fan-out ограничены одной БД; все потребители тянут из одной таблицы; ретеншн журнала не автоматизирован | Kafka-совместимый брокер между адаптерами и normalizer/projector (vision, «Варианты исполнения»), раздельные consumer groups, ретеншн и компакция топиков. Inbox остаётся как журнал для replay либо заменяется топиком | L |
| 1.5 | PostgreSQL: один экземпляр, `pg_dump` вручную, без PITR | Потеря журнала и crosswalk между backup'ами; журнал — источник replay, его потеря не восстанавливается из графа | HA (Patroni или управляемый сервис), WAL-архивация и PITR, регулярные restore drills, пулер соединений | M |
| 1.6 | S3 — один SeaweedFS без репликации | Потеря raw payload = потеря возможности replay и provenance-доказательств | Управляемое S3 или кластер с репликацией, версионирование и lifecycle-политики бакета | S–M |
| 1.7 | Образы: плавающий тег `neo4j:5-community`; нет сканирования и подписи образов | Минорное обновление Neo4j ломает restore старой копии (README); уязвимости базовых образов не отслеживаются | Точные теги и дайджесты, сканер образов в CI, SBOM, подпись (техдолг UNLOCKER-215 закрывает тег в тестах, не в compose) | S |

## 2. Доступ и безопасность

| # | Пробел | Риск | Целевое решение | Оценка |
|---|---|---|---|---|
| 2.1 | Keycloak в dev-режиме внутри стенда, bootstrap-админ, секрет клиента `archrag-demo` в `.env.example` | Демо-секреты известны всем, кто видел репозиторий | Внешний IdP организации (OIDC): клиенты по каждому агенту/команде, ротация секретов, короткие токены, отзыв | M |
| 2.2 | Scope'ы грубые: `architecture.read` на все активы, `architecture.admin` на админку | Любой агент с read видит весь граф, нет разграничения по доменам и по tenant | Доменная авторизация: claim → набор доменов/окружений, фильтр в `graph-query-core` на уровне шаблонов и негативные тесты на утечку между доменами; аудит обращений по субъекту | L |
| 2.3 | Аннотации MCP-tools: в `tools/list` у каждого tool `readOnlyHint=false`, `destructiveHint=true` (значения по умолчанию Spring AI, в коде не заданы) | MCP-клиенты и политики подтверждения считают read-only tools потенциально разрушающими: лишние запросы подтверждения, неверная классификация в аудите | Явно выставить `readOnlyHint=true`, `destructiveHint=false`, `idempotentHint=true`, `openWorldHint=false` в описании каждого tool; тест на `tools/list` | S |
| 2.4 | TLS: самоподписанный CA, `bolt+ssc` | Нет проверки подлинности Neo4j и proxy | Доверенный CA/сертификаты организации, `bolt+s`, mTLS между сервисами при требовании безопасности | S–M |
| 2.5 | Нет rate limiting и квот на агента | Один агент может занять пул соединений Neo4j; защищают только таймауты и бюджеты запроса (`max-nodes`, `max-paths`, `timeout`) | Квоты по субъекту на gateway, лимит одновременных запросов на tool, метрики отказов по квоте | M |
| 2.6 | Тексты источников недоверенные (описания, документы), но фильтра на prompt injection на выдаче нет | Описание актива может содержать инструкции для агента-потребителя | Маркировка полей как недоверенных в ответе tool, ограничение длины, документированный контракт для клиентов; при добавлении `Document`/chunks — отдельная проверка | M |
| 2.7 | Консоль: scope `architecture.admin` без ролевого ограничения; Keycloak на `127.0.0.1` открывает и master-админку (ADR [0026](adr/0026-admin-console-readonly-loopback.md)). Принято владельцем как ограничение PoC (2026-10-08), ADR 0026 | Любой пользователь realm может получить токен консоли через клиент `archrag-admin-console` | Scope mapping `architecture.admin` → роль `archrag-console-admin` (с отдельным клиентом для service account), loopback-блок proxy только для `/realms/archrag/` | S |

## 3. Эксплуатация

| # | Пробел | Риск | Целевое решение | Оценка |
|---|---|---|---|---|
| 3.1 | Мониторинг: метрики есть (E5.3), алертов и дежурств нет; Grafana на `127.0.0.1` | Рост sync lag, DLQ или ошибок никто не заметит | Алерты на `archrag_ingestion_sync_lag_seconds`, `archrag_ingestion_dlq_open`, долю не-`PROJECTED` и p95 tools; on-call, runbook на каждый алерт, логи и трейсы в централизованное хранилище | M |
| 3.2 | Нет целевых RPO/RTO, restore drills и расписания backup | Неизвестно, сколько данных и времени теряется при аварии; backup делает человек | Зафиксировать RPO/RTO, расписание и ретеншн backup, регулярная проверка восстановления (сценарий `backup-restore-check.sh` — основа) | M |
| 3.3 | Нет SLO и нагрузочной модели | Замеры PoC — на заглушках и на одном хосте, это ориентир, а не обещание | Нагрузочные тесты на реальном объёме активов, SLO на latency tools и на «источник → граф», capacity planning Neo4j (память под page cache) | M |
| 3.4 | Обновления: нет стратегии миграций без простоя | Flyway и схема Neo4j применяются при старте `ingestion`; откат миграции не предусмотрен | Правила совместимости миграций (expand/contract), canary-раскатка, процедура отката | M |
| 3.5 | Мастер-системы — заглушки | Контракты реальных EAM/SCM/CMDB/deploymap не проверены: аутентификация, пагинация, лимиты, форматы, объём | Подключение реальных источников по очереди с контрактными тестами и пилотом на одном домене | L |

## 4. Известные пробелы самого PoC

Это не «production-расширения», а поведение, которое нужно знать до пилота.

| # | Пробел | Где зафиксирован | Что делать |
|---|---|---|---|
| 4.1 | После restore удаления, выполненные reconciliation после backup, replay не повторяет (маркеры `snapshot-complete` пропускаются) | README, «Backup и restore» | После restore запускать `POST /admin/reconcile/{source}` или новый snapshot; автоматизировать в `restore.sh` |
| 4.2 | Адаптер каждого источника — ровно один экземпляр, замок snapshot действует только внутри процесса | README, «Ограничения E5.1» | Распределённый замок (advisory lock PostgreSQL) или leader election при >1 реплике |
| 4.3 | `GET /health` адаптера остаётся UP после падения потока polling/reconciliation | README, «Ограничения E5.1» | Health, зависящий от времени последнего успешного цикла; алерт на отсутствие polling |
| 4.4 | Задержка «источник → граф» на PoC определяется интервалом polling адаптера (по умолчанию 30 с): p95 лежит близко к порогу 30 с | [`04-poc-measurements.md`](04-poc-measurements.md) | Webhook-путь от источников и/или уменьшение интервала; для production — webhook плюс reconciliation (vision) |
| 4.5 | Технический долг: UNLOCKER-215 (точный тег Neo4j в интеграционных тестах), UNLOCKER-218 (устаревшие нетемпоральные связи не снимаются при новой версии записи), UNLOCKER-219 (`HAS_DEPLOYMENT` из DEPLOYMAP получает `validFrom = null`), UNLOCKER-220 (`F2AcceptanceIT` использует копию вместо `McpTestJwt`), UNLOCKER-223 (`JournalDispatcherIT`: таймаут под нагрузкой) | задачи Multica | Закрыть до пилота; 218 и 219 влияют на корректность выдачи |
| 4.6 | `explain_provenance` (F4) на момент замеров не вошёл в `develop`: его latency не измерена | [`04-poc-measurements.md`](04-poc-measurements.md) | Повторить `measure.sh` после вливания F4 |
