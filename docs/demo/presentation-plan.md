## 1. Вводная

- **Аудитория:** разработчики и архитекторы (решение владельца). Акцент: архитектура и модель, provenance, безопасность и read-only, устройство MCP tools (Inspector), живой агент в Claude Code. Бизнес-эффект и стоимость не обсуждаются.
- **Цель:** слушатель уходит с тремя утверждениями. (1) Граф архитектуры собирается из мастер-систем и остаётся их производной, а не новым «источником истины». (2) Каждый ответ можно проверить: у него есть источник, время и признак свежести. (3) Агенту безопасно дать доступ, потому что у него нет ни записи, ни произвольного Cypher.
- **Данные:** вымышленный банк «Nordhaven Bank» ([dataset.md](dataset.md)): 10 ИТ-систем, 27 сервисов, 41 развёртывание, 27 записей CMDB. Мастер-системы в PoC — заглушки ([ADR 0010](../adr/0010-master-systems-are-stubs.md)); об этом нужно сказать в первых минутах.
- **Длительность владельцем не задана.** Даны два варианта:

## 3. Блоки

### Блок 1. Проблема и зачем граф архитектуры

**Ключевая мысль.** Ответ на вопрос «что сломается, если упадёт эта ВМ» лежит в четырёх системах, и ни одна не отвечает целиком.

**Тезисы докладчика.**

1. Архитектурные факты распределены: ИТ-системы и владельцы в EAM, сервисы и репозитории в SCM, хосты в CMDB, развёртывания и commit в deploy map ([dataset.md, п. 1–2](dataset.md#1-принципы)).
2. Вопросы агента сквозные: «где работает система», «что затронет отказ хоста», «откуда это известно». Ответ — путь через несколько источников, то есть граф.
3. Это не классический GraphRAG из текста: сущности и связи уже структурированы в мастер-системах, LLM-извлечение графа не нужно ([00-vision.md, «Почему это GraphRAG»](../00-vision.md#почему-это-graphrag)).
4. Граф — производная read-only витрина; мастер-системы остаются владельцами данных ([ADR 0001](../adr/0001-neo4j-derived-read-model.md)).
5. Честно о границах: источники в PoC — заглушки, граф крошечный, замеры — ориентир.

**Материал.** Схема источников из [dataset.md, п. 2](dataset.md#2-обзор) (диаграмма доменов и систем). Для сквозного примера — сценарий 4 ([impact отказа ВМ](scenarios.md#сценарий-4-impact-отказа-вм)), показывать только как тизер, без запуска.

**Время.** 5 мин (сокращённый — 3: тезисы 1, 2 и 4).

**Вопросы зала.**

- *Чем это отличается от CMDB с хорошим поиском?* CMDB — один из четырёх источников и мастер только для хостов; сквозной путь «хост → развёртывание → сервис → система → зависящие сервисы» собирается из четырёх источников ([scenarios.md, сценарий 4](scenarios.md#сценарий-4-impact-отказа-вм)).
- *Почему не векторный поиск по документации?* Для инвентаризации, трассировки и impact нужны детерминированные обходы по фактам; векторный и полнотекстовый поиск уместны для описаний, а не для путей ([00-vision.md, «Почему это GraphRAG»](../00-vision.md#почему-это-graphrag)).
- *Зачем граф, если есть Backstage?* В репозитории сравнения нет; ответ — вне материалов, лучше не отвечать «по памяти».

### Блок 2. Архитектура: четыре контура, C4

**Ключевая мысль.** Запись и чтение разделены архитектурно: контуры 1–3 пишут, контур 4 только читает, и это закреплено направлением зависимостей модулей.

**Тезисы докладчика.**

1. Четыре контура: сбор (адаптеры), журнал и идентичность (PostgreSQL inbox + S3 raw, normalizer, identity, projector), витрина (Neo4j), доступ (MCP, консоль) — [ADR 0002](../adr/0002-four-contours.md), диаграмма в [architecture.md, п. 2](../../_reversa_sdd/architecture.md#2-назначение-и-четыре-контура).
2. Источник → адаптер (polling + webhook как триггер, [ADR 0039](../adr/0039-webhook-is-trigger-only.md)) → журнал → проекция в Neo4j. Журнал и raw позволяют пересобрать граф ([data-model, п. 1](../02-data-model.md#1-обзор)).
3. `access/*` не зависит от `ingestion/*` и `adapters/*`; source DTO не выходят за адаптер и normalizer ([architecture.md, п. 4](../../_reversa_sdd/architecture.md#4-ключевые-архитектурные-инварианты)).
4. Контейнеры и что важно архитектору: разделение прав записи на уровне учёток приложения, один экземпляр ingestion, `mcp-server` масштабируется горизонтально ([c4-containers.md, п. 3](../../_reversa_sdd/c4-containers.md#3-что-важно-архитектору)).
5. Событие в бою: идемпотентность по `source + eventId`, `IGNORED_OLD_VERSION`, checkpoint после коммита Neo4j. Подробный показ — сценарий 8.
6. Event backbone в PoC — PostgreSQL inbox, Kafka — production ([ADR 0006](../adr/0006-postgres-inbox-event-backbone.md)).

**Материал.** Диаграммы по порядку показа: [c4-context.md, п. 1](../../_reversa_sdd/c4-context.md#1-диаграмма) → [c4-containers.md, п. 1](../../_reversa_sdd/c4-containers.md#1-диаграмма) → [c4-components.md, п. 1.1](../../_reversa_sdd/c4-components.md#11-диаграмма) (`ingestion`, только если есть время) → [c4-components.md, п. 2.1](../../_reversa_sdd/c4-components.md#21-диаграмма) (`mcp-server` и `graph-query-core`). Схему потока в хранилищах — из [02-data-model.md, п. 1](../02-data-model.md#1-обзор).

**Время.** 8 мин (сокращённый — 5: context, containers, одна диаграмма `mcp-server`).

**Вопросы зала.**

- *Почему Neo4j Community и не Enterprise?* Решение PoC: платных возможностей нет; read-only и разделение reader/writer обеспечивает приложение. В production это один из главных пробелов ([ADR 0004](../adr/0004-neo4j-community-constraints.md), [05-production-gap-list.md, п. 1.2–1.3](../05-production-gap-list.md#1-платформа-и-данные)).
- *Почему PostgreSQL, а не Kafka?* Для PoC хватает inbox с одним потребителем; ограничения (пропускная способность, fan-out) и целевое решение записаны в [gap list, п. 1.4](../05-production-gap-list.md#1-платформа-и-данные) и [ADR 0006](../adr/0006-postgres-inbox-event-backbone.md).
- *Можно ли пересобрать граф с нуля?* Да, из журнала и raw в S3; граф — производная ([ADR 0001](../adr/0001-neo4j-derived-read-model.md)). Критерий 4 видения требует эквивалентности после полного rebuild ([00-vision.md, «Критерии готовности PoC»](../00-vision.md#критерии-готовности-poc)); где именно он проверен, в этом плане не сверялось.
- *Сколько экземпляров можно запускать?* `mcp-server` — сколько угодно, адаптеры и `ingestion` — по одному ([c4-containers.md, п. 3](../../_reversa_sdd/c4-containers.md#3-что-важно-архитектору), [gap list, п. 4.2](../05-production-gap-list.md#4-известные-пробелы-самого-poc)).

### Блок 3. Модель данных и provenance

**Ключевая мысль.** У каждого узла есть `gid`, а «откуда это известно» хранится отдельно: записи источников утверждают узел, и мастер определён для каждого поля.

**Тезисы докладчика.**

1. Внутренний `gid: UUID` на всех узлах; внешние идентификаторы не ключ графа, а отдельные `SourceRecord` ([00-vision.md, «Идентичность узлов»](../00-vision.md#идентичность-узлов), [ADR 0003](../adr/0003-gid-and-source-record-identity.md)).
2. Схема утверждений: `(SourceSystem)-[:OWNS_RECORD]->(SourceRecord)-[:ASSERTS]->(узел)`, авторитет `MASTER` или `SUPPLEMENTARY` ([02-data-model.md, п. 2.3](../02-data-model.md#23-жизненный-цикл-и-provenance)).
3. Мастер определяется матрицей **на уровне поля**: `Deployment` — deploy map + Helm, система и платформа — EAM, сервис — SCM ([02-data-model.md, п. 3](../02-data-model.md#3-authority-matrix), [ADR 0008](../adr/0008-authority-matrix-field-level.md)).
4. Время жизни: `firstSeenAt`/`lastSeenAt`, `isCurrent`, `deletedAt`; физического удаления нет, tombstone ([ADR 0020](../adr/0020-tombstone-instead-of-hard-delete.md)). Структурные связи временные: закрытая связь получает `validTo` ([ADR 0028](../adr/0028-structural-relations-temporal.md)).
5. Значение вне словаря не теряется: `criticality=CRITICAL` из EAM лежит в `criticalityRaw` ([ADR 0040](../adr/0040-source-dictionary-values-policy.md)); демонстрируется в сценарии 1.
6. Идентичность: совпадение кандидатов не склеивается автоматически, решает оператор ([ADR 0019](../adr/0019-identity-resolution-no-auto-merge.md)).
7. Конфликт источников виден, а не выбирается молча: маркер `conflicts` и `conflictState` ([scenarios.md, сценарий 5](scenarios.md#сценарий-5-происхождение-данных-и-конфликты)).

**Материал.**

- Диаграмма модели: [02-data-model.md, п. 2.4](../02-data-model.md#24-диаграмма); таблицы узлов и связей — п. 2.1–2.2, показывать фрагментом.
- Словарь типов: [data-dictionary.md, A.1–A.5](../../_reversa_sdd/data-dictionary.md#a1-узлы-nodedata-sealed-11-вариантов--cmnodenodedatajava9-11).
- **`graph.html`** (офлайн, двойной клик): раскладка «по слоям и доменам», затем «по окружениям»; в левой панели фильтры меток, окружений и источников; карточка узла с provenance; бейджи «конфликт», «stale», «удалён», «неразрешённая ссылка»; переключатель «Сценарий» подсвечивает узлы сценариев 1–10 ([platform/docker/README.md, «Визуализация графа»](../../platform/docker/README.md)). Показ: найти `Payments Core` поиском, открыть карточку, переключить сценарий 5 (конфликт) и сценарий 9 (закрытый узел).
- Скриншоты для резерва: `S-03`, `S-04`, `S-05` из [списка скриншотов](#5-скриншоты-которые-нужно-снять).

**Время.** 8 мин (сокращённый — 5: тезисы 1–3, 5 и `graph.html` с одной карточкой).

**Вопросы зала.**

- *Почему `gid`, а не ID из EAM?* Совпадение значений в разных системах не означает тождество сущностей; внешняя идентичность лежит в `SourceRecord` ([00-vision.md, «Идентичность узлов»](../00-vision.md#идентичность-узлов)).
- *Что будет, если два источника утверждают разное значение свойства?* Мастер задан матрицей; конфликт значения свойства на текущих мапперах не возникает и покрыт тестом `SourceConflictIT`; в демо показан конфликт связей ([scenarios.md, сценарий 5](scenarios.md#сценарий-5-происхождение-данных-и-конфликты)).
- *Почему граф не показывает значения конфликтующих свойств?* Только имена свойств: значения диссидента из другой системы не отдаются через MCP; детали смотрит человек в консоли ([scenarios.md, сценарий 5](scenarios.md#сценарий-5-происхождение-данных-и-конфликты)).
- *Где домен как узел?* Его нет: домен — текст `Domain: …` в `description` ([dataset.md, п. 8](dataset.md#8-вопросы-архитектору-и-ограничения)).

Параллельно открытый `graph.html` с переключателем «Сценарий» N показывает затронутые узлы.

**Вопросы зала.**

- *Агент ответил иначе, чем скрипт. Это баг?* Нет: выбор tool и формулировка недетерминированы; детерминирован ответ tool на одинаковые аргументы. Контракт держат эталоны и `demo-check.sh` ([scenarios.md, приложение](scenarios.md#приложение-соответствие-скриптов-эталонов-и-кейсов)).
- *Как быстро агент видит изменение в источнике?* Ограничено циклом опроса адаптера (по умолчанию 30 с) и webhook-триггером; замеры в [блоке 6](#блок-6-метрики-poc).
- *Можно ли через агента посмотреть прежний commit?* Нет, закрытые связи через MCP не отдаются; новый вопрос — новый шаблон ([scenarios.md, сценарий 8](scenarios.md#сценарий-8-передеплой-смена-commit), [ADR 0018](../adr/0018-domain-tools-not-arbitrary-cypher.md)).
- *Почему `DEPENDS_ON` из EAM всегда `stale`?* Известное ограничение: связь утверждена записью без узла и не несёт `sourceFetchedAt` ([scenarios.md, сценарий 3](scenarios.md#сценарий-3-зависимости-trace), [dataset.md, п. 8](dataset.md#8-вопросы-архитектору-и-ограничения)). Не скрывать, если спросят.

### Блок 5. Безопасность, read-only и MCP изнутри (Inspector)

**Ключевая мысль.** Агент получает ровно шесть read-only tools; всё, что делает Claude Code, — обычные вызовы протокола, а защита от записи обеспечена приложением, а не СУБД.

**Тезисы докладчика.**

1. **Нет записи и нет произвольного Cypher:** поверхность атаки — фиксированные параметризованные шаблоны ([ADR 0018](../adr/0018-domain-tools-not-arbitrary-cypher.md)). Метки и типы связей — из allowlist, глубина — проверенное число в диапазоне.
2. **Read-only обеспечивает приложение:** `executeRead`, сессия `AccessMode.READ`, `EXPLAIN` обязан дать `READ_ONLY`; `mcp-server` читает под `archrag_reader`, учётных данных writer у него нет. Ролей в Neo4j Community нет ([ADR 0005](../adr/0005-readonly-mcp-by-application.md), [scenarios.md, сценарий 7](scenarios.md#сценарий-7-безопасность-и-границы)).
3. **Аутентификация:** JWT на каждый запрос (подпись, issuer, audience); Spring AI MCP starter сам аутентификацию не включает, scope проверяет `ToolScopeFilter`, tool без записи в `tool-scopes` закрыт по умолчанию.
4. **Границы — ошибки, а не тихое усечение:** `maxDepth` 1..6, `limit` 1..50, `query` ≤ 200, тело ≤ 1 МБ.
5. **Аудит:** каждый `tools/call` пишется в `archrag.audit.mcp` и в метрику с решением `ALLOWED`/`DENIED_*`; токены и аргументы не логируются ([ADR 0038](../adr/0038-access-audit-channels.md)).
6. **Недоверенные тексты:** описания из источников — данные; фильтра prompt injection на выдаче в PoC нет ([gap list, п. 2.6](../05-production-gap-list.md#2-доступ-и-безопасность)). Сказать прямо.
7. **Admin REST отдельно:** replay, rebuild, reconcile, approve — не MCP и не наружу; токен агента scope `architecture.admin` не имеет ([c4-context.md, п. 2](../../_reversa_sdd/c4-context.md#2-персоны)).

**Показ (по шагам).**

1. **Сценарий 7 скриптом** `demo/07-access.sh` (2 мин): 401 без токена, 401 с испорченной подписью, 403 для `upsert_asset`, 200 с токеном, ошибки границ, у всех tools `readOnly`/`destructive` как положено ([scenarios.md, сценарий 7](scenarios.md#сценарий-7-безопасность-и-границы)). Эталон — `expected/07-*.json`, `expected/tools-list.json`.
2. **MCP Inspector** (3–4 мин, `demo/inspector.sh`; версию пакета нужно задать явно, непиннованный не запускается): `initialize` (режим `STATELESS`, `serverInfo`), `tools/list` (шесть tools, `inputSchema`, `annotations`), сырой `tools/call` (ответ — **строка с JSON** в `result.content[0].text`; ошибка tool — HTTP 200 и `isError=true`), отказ без токена (401 с `WWW-Authenticate`) ([scenarios.md, п. 5](scenarios.md#5-протокол-изнутри-mcp-inspector)).
3. Живой вопрос агенту: «Создай в каталоге новый сервис» — ожидаемо ответит, что подходящего tool нет ([scenarios.md, сценарий 7, «Живой агент»](scenarios.md#сценарий-7-безопасность-и-границы)).

**Ограничение стенда, которое нужно проговорить:** отказ «токен без нужного scope» (`insufficient_scope`) на стенде получить нельзя, Keycloak всегда выдаёт клиенту `archrag-demo` scope `architecture.read`. Проверяют его тесты mcp-server; на показе его заменяет 403 для tool без scope ([scenarios.md, сценарий 7](scenarios.md#сценарий-7-безопасность-и-границы)).

**Материал.** [03-interfaces.md, раздел 2](../03-interfaces.md#2-mcp-сервер), [scenarios.md, сценарий 7](scenarios.md#сценарий-7-безопасность-и-границы), [scenarios.md, п. 5](scenarios.md#5-протокол-изнутри-mcp-inspector), `expected/07-*.json`, `expected/tools-list.json`. Скриншоты `S-12`, `S-13`, `S-14`.

**Время.** 10 мин: сценарий 7 — 2, тезисы — 3, Inspector — 4, вопрос агенту — 1. Сокращённый — 5: тезисы 1, 2, 3 (2 мин), Inspector только `tools/list` и сырой `tools/call` (3 мин); сценарий 7 скриптом выпадает.

**Вопросы зала.**

- *Если защиту держит приложение, а не БД, что мешает ошибке в шаблоне дать запись?* Ничего на уровне СУБД: поэтому в коде только `executeRead`, перед первым выполнением шаблона проверяется `EXPLAIN`, а учётных данных writer у `mcp-server` нет. На уровне БД защита появится с Enterprise RBAC ([gap list, п. 1.3](../05-production-gap-list.md#1-платформа-и-данные)).
- *Что, если агент подставит Cypher в `query`?* Это обычная строка поиска: параметр, а не часть запроса ([scenarios.md, сценарий 7](scenarios.md#сценарий-7-безопасность-и-границы)).
- *Может ли один агент видеть всё?* Да: scope `architecture.read` даёт доступ ко всему графу, разграничения по доменам нет ([gap list, п. 2.2](../05-production-gap-list.md#2-доступ-и-безопасность)).
- *Почему `readOnlyHint` не считается защитой?* Это подсказка клиенту; защита — `executeRead` ([scenarios.md, п. 3](scenarios.md#3-как-читать-ответ-mcp)).
- *Есть ли rate limit?* Нет; защищают только таймауты и бюджеты запроса ([gap list, п. 2.5](../05-production-gap-list.md#2-доступ-и-безопасность)).

### Блок 6. Метрики PoC

**Ключевая мысль.** Цифры — ориентир на заглушках и одном загруженном хосте, а не SLO.

**Тезисы докладчика (цифры только из [04-poc-measurements.md](../04-poc-measurements.md)).**

1. Latency tools, клиентский p95 через TLS-proxy и OIDC: 0,13–0,43 с последовательно, 0,19–0,58 с при 4 потоках; ошибок — 0 из 1200 вызовов.
2. «Источник → граф», webhook (гейт критерия 2): p95 2,1 с при пороге 30 с. Polling (страховка): p95 28,6 с при пороге 35 с (интервал 30 с + 5). N=20 на путь.
3. Throughput ingestion ≈ 3,4 события/с, sync lag максимум 23,6 с во время burst из 200 событий и 0 после.
4. Ошибок обработки, `QUARANTINED` и роста DLQ нет; не-`PROJECTED` исходы (`IGNORED_OLD_VERSION` 18, `DUPLICATE` 2) — штатная дедупликация повторной доставки.
5. Глубина: `maxDepth` 1…6 принимается, 7 и 0 отклоняются ошибкой; на демо-графе достижимо 6 узлов и 5 путей, бюджеты узлов и путей не срабатывают.
6. Лимиты сервера: глубина 6, узлов 500, путей 50, таймаут 5 с, ответ 512 КБ ([04-poc-measurements.md, «Ограничения глубины и бюджета»](../04-poc-measurements.md#ограничения-глубины-и-бюджета)).

**Оговорки, которые нужно произнести:** хост общий (load average 11–20 на 8 ядрах), граф крошечный, `N=20` даёт грубый p95, webhook-путь идёт мимо TLS-proxy ([04-poc-measurements.md, «Ограничения замеров»](../04-poc-measurements.md#ограничения-замеров)). Прогноз на «десятки тысяч активов» в документе — оценка по одному числу, не замер; не называть как факт.

**Материал.** Таблицы «MCP tools» и «Источник → граф» из [04-poc-measurements.md, «Результаты»](../04-poc-measurements.md#результаты); критерии готовности — [00-vision.md](../00-vision.md#критерии-готовности-poc). Резерв: текст документа, живой прогон `measure.sh` на показе не делается (около 18 минут).

**Время.** 5 мин (сокращённый — 2: пункты 1, 2 и оговорка).

**Вопросы зала.**

- *Почему polling p95 так близок к порогу?* Задержку задаёт ожидание следующего цикла адаптера (равномерно от 0 до 30 с), а не проекция; поэтому гейтом выбран webhook-путь по решению владельца ([04-poc-measurements.md, «Выводы»](../04-poc-measurements.md#выводы), [gap list, п. 4.4](../05-production-gap-list.md#4-известные-пробелы-самого-poc)).
- *Выдержит ли это реальный объём?* Не проверено: нагрузочных тестов на реальном объёме нет ([gap list, п. 3.3](../05-production-gap-list.md#3-эксплуатация)).
- *Почему throughput так низок?* Один `ingestion` разбирает очередь последовательно; для объёма нужны Kafka и параллельные потребители ([04-poc-measurements.md, «Выводы»](../04-poc-measurements.md#выводы), [gap list, п. 1.4](../05-production-gap-list.md#1-платформа-и-данные)).
- *Что с `explain_provenance`, он вошёл в замеры?* Да, в таблице замеров есть строка с p95 385 мс последовательно (в gap list п. 4.6 запись устарела, см. [п. 7](#7-расхождения-в-исходных-документах-для-ведущего)).

### Блок 7. Разрыв до production

**Ключевая мысль.** PoC доказывает идею, но до пилота и до эксплуатации остаётся конкретный и оценённый список работ.

**Тезисы докладчика.**

1. Для **пилота** обязательны 2.1 (внешний IdP), 2.2 (доменная авторизация), 2.3 (аннотации tools), 3.1 (алерты), 3.2 (RPO/RTO и backup), 3.5 (реальные источники) и закрытие 4.1, 4.5 ([gap list, «Порядок работ»](../05-production-gap-list.md#порядок-работ)).
2. Для **промышленной эксплуатации** добавляются Kubernetes, кластер Neo4j с лицензией Enterprise и брокер (1.1–1.5) — самая дорогая часть; оценка L.
3. Две вещи, которые влияют на корректность выдачи уже сейчас: UNLOCKER-218 (устаревшие нетемпоральные связи не снимаются при новой версии записи) и UNLOCKER-219 (`HAS_DEPLOYMENT` из DEPLOYMAP получает `validFrom = null`) ([gap list, п. 4.5](../05-production-gap-list.md#4-известные-пробелы-самого-poc)).
4. Оценки (S — дни, M — 1–3 недели, L — месяц и более) даны для команды из двух разработчиков, без согласований и закупок.
5. Решение по лицензии Neo4j Enterprise принадлежит владельцу ([gap list, п. 1.2](../05-production-gap-list.md#1-платформа-и-данные)).

**Материал.** [05-production-gap-list.md](../05-production-gap-list.md): показывать сводной таблицей из четырёх-пяти строк (1.2, 1.3, 2.2, 3.5, 4.5), не читать весь документ. Скриншот не нужен.

**Время.** 5 мин (сокращённый — 2: тезисы 1, 2 и 5).

**Вопросы зала.**

- *Сколько стоит довести до production?* Оценок в деньгах в репозитории нет. Есть грубые оценки трудозатрат в S/M/L; сумму не называть.
- *Можно ли без Enterprise?* Для пилота — да, с оговорками по отказоустойчивости и RBAC; для промышленной эксплуатации — решение владельца ([gap list, п. 1.2–1.3](../05-production-gap-list.md#1-платформа-и-данные)).
- *Как подключаются реальные EAM и CMDB?* Не проверено: контракты реальных систем не сверены, это пункт 3.5 (L) с пилотом на одном домене ([gap list, п. 3.5](../05-production-gap-list.md#3-эксплуатация)).
- *Что с утечкой данных через описания?* Недоверенные тексты не фильтруются на выдаче; целевое решение — маркировка полей и контракт для клиентов ([gap list, п. 2.6](../05-production-gap-list.md#2-доступ-и-безопасность)).
