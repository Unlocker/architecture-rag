  1. Arch RAG

    Операционный граф знаний об архитектуре предприятия. Обзор для нового разработчика.

  2. Назначение

    Arch RAG - операционный граф знаний об архитектуре предприятия, а не «GraphRAG из документов»: мастер-системы остаются владельцами данных, Neo4j - производная read-only витрина, адаптеры поддерживают её актуальность, а MCP-сервер даёт ИИ-агентам ограниченный набор предметных read-only операций. Потребители - ИИ-агенты (через MCP) и операторы (через read-only админ-консоль).

    Источник: soul.md, раздел 1.

  3. Центральные сущности

    • ITSystem: ИТ-система предприятия (корень иерархии). Связи: USES_SOLUTION→Solution, DECOMPOSED_INTO→Service, OWNED_BY→Tea...
    • Solution / Platform: Решение и платформа, на которой оно построено. Связи: USES_PLATFORM
    • Service: Сервис - единица разработки и развёртывания. Связи: IMPLEMENTED_IN→Repository, HAS_DEPLOYMENT→Deployment, DEPE...
    • Repository: Git-репозиторий исходного кода. Связи: цель IMPLEMENTED_IN, DEPLOYED_FROM {commit}
    • Deployment: Развёртывание сервиса в окружении. Связи: IN_ENVIRONMENT→Environment, RUNS_ON→ComputeInstance/Namespace, DEPLO...
    • Environment / ComputeInstance (VirtualMachine, PhysicalServer) / Namespace / KubernetesCluster: Окружение и инфраструктура исполнения. Связи: HOSTED_ON, PART_OF
    • Team: Владелец систем и сервисов. Связи: цель OWNED_BY
    • SourceSystem / SourceRecord / SyncRun: Provenance: кто и когда утверждал факт. Связи: OWNS_RECORD, ASSERTS, PROCESSED

  7. Основополагающие решения

    • D1: Neo4j - производная read-only витрина; источник истины - мастер-системы
    • D2: Идентичность: `gid` + `SourceRecord {source, sourceType, sourceId}`; `sourceId` - без префикса системы
    • D3: Postgres inbox как event backbone за интерфейсами `EventJournal`/`CanonicalEventPublisher`; raw payload в S3 (SeaweedFS)
    • D4: Authority matrix на уровне полей и связей; identity resolution без авто-слияния
    • D5: Tombstone вместо hard delete; удаление только после `snapshot-complete`; структурные связи темпоральны
    • D6: Агентам - предметные tools с параметризованными шаблонами; read-only обеспечивает приложение, не Neo4j Community
    • D7: Java 21 + Spring Boot 4 + Spring AI 2 + Maven multi-module; четыре контура как модули; Docker Compose стенд
    • D8: Мастер-системы в PoC - заглушки; `Deployment` берётся из deploy map + Helm charts

    Подробности: ADR и soul.md.
