adapters/eam-adapterконтур: adaptersфайлов кода: 11LOC: 529LOC тестов: 790достоверность: 86%md-файлов: 15

Кратко

Модуль привязывает общий каркас адаптеров (adapter-core: webhook, polling, snapshot, запись в inbox) к источнику SourceSystem.EAM (EA/EamAdapter.java:19). Своей логики приёма событий у модуля нет: он поставляет коннектор - читателя eam-api («EAM Tool API», docs/eam-api.yaml, формат ArchObject) и склейку с «старой заглушкой» (TEAM, SERVICE_DEPENDENCY). Доступа к Neo4j, PostgreSQL и S3 у модуля нет: журнал и raw-хранилище приходят интерфейсами event-schemas (EA/EamAdapter.java:33-39, 62-71) 🟢.

Метки в specs: подтверждено кодом 198, выведено 61, пробелов 8.

Требования

Полный текст: requirements.md (разделы с трассировкой кода и диаграммами в выжимку не включены).

Responsibilities
  • Читать списки platforms, itproducts, itsystems реального формата EAM постранично и отдавать SourceChange с sourceType ∈ {PLATFORM, SOLUTION, IT_SYSTEM} и sourceId = id объекта 🟢 (EA/EamApiConnector.java:51-54, 175-183).
  • Вести непрозрачный курсор: полный snapshot, инкрементальный проход по sort=-mtime до водяного знака и состояние «между проходами» 🟢 (EA/EamApiCursor.java).
  • Соблюдать лимиты источника: page_size ≤ 500, ≤ 10 запросов/с, одно ожидание по Retry-After при 429 🟢 (EA/EamApiConnector.java:45, 56-57, 205-219, 249-260).
  • Склеить eam-api и legacy-заглушку в один коннектор одного источника EAM с одним snapshot и одним маркером snapshot-complete 🟢 (EA/CompositeEamConnector.java:50-70).
  • Собрать SourceAdapter для EAM в двух режимах: «только legacy» и «eam-api + legacy» 🟢 (EA/EamAdapter.java:33-39, 62-71).
  • Не светить токен: EamApi.toString, исключения и логи без токена и тел ответов 🟢 (EA/EamAdapter.java:49-52, EA/EamApiConnector.java:186, 244).

Не входит в модуль: разбор attrs и построение GraphCommand (это ingestion/normalizer, EamMapper), запись в inbox/S3 (adapter-core), reconcile и tombstone (graph-projector, Reconciler), сами заглушки (platform/source-stubs).

Бизнес-правила
  • BR-1. sourceId - целочисленный id объекта EAM без префикса: Long.toString(id); строковый или нецелый id - ошибка 🟢 (EA/EamApiConnector.java:175, 182, 190-195; тест EamApiConnectorTest.malformedIntegerIdIsRejected, ET/EamApiConnectorTest.java:212; решение владельца 2026-10-04, docs/06-eam-integration.md §«Схема синхронизации», п. 3).
  • BR-2. Порядок чтения типов фиксирован: PLATFORM → SOLUTION → IT_SYSTEM 🟢 (EA/EamApiConnector.java:51-54).
  • BR-3. Тип EAM для «ИТ-решения» - itproducts, единственное место выбора - константа SOLUTION_TYPE 🟢 (EA/EamApiConnector.java:48); подтверждено владельцем 2026-10-10 (docs/06-eam-integration.md §«Решения», п. 1).
  • BR-4. Коннектор отдаёт только UPSERT с Completeness.COMPLETE; DELETE не порождается. Исчезновение объекта (архивация) обнаруживает snapshot + reconcile (ADR 0020) 🟢 (EA/EamApiConnector.java:182-183).
  • BR-5. snapshotComplete=true - только на последней странице последнего типа полного прохода (cursor == null) 🟢 (EA/EamApiConnector.java:131); в составном коннекторе - только после последней страницы legacy-половины 🟢 (EA/CompositeEamConnector.java:65-69).
  • BR-6. Курсор нового формата: W,<watermark> между проходами. Водяной знак - максимальный datetime, увиденный коннектором; он не убывает внутри прохода 🟢 (EA/EamApiConnector.java:111, 120-122, EA/EamApiCursor.java:39-45).
  • BR-7. Чужой (не составной) курсор в CompositeEamConnector не падает навсегда: чтение идёт заново как инкремент (без snapshot-complete и без удалений) 🟢 (EA/CompositeEamConnector.java:72-85).
  • BR-8. Типы legacy-половины ограничены TEAM, SERVICE_DEPENDENCY; IT_SYSTEM (и любой иной тип) из legacy отбрасывается молча 🟢 (EA/CompositeEamConnector.java:30, 61).
  • BR-9. datetime == null превращается в Instant.EPOCH 🟢 (EA/EamApiConnector.java:180-181); последствия - questions.md Q-3.
  • BR-10. Для маршрутизации fetchById важен только sourceType: PLATFORM/SOLUTION/IT_SYSTEM → eam-api, TEAM/SERVICE_DEPENDENCY → legacy, прочее - пусто 🟢 (EA/CompositeEamConnector.java:88-96).

Конфигурация (снаружи модуля)

Модуль сам конфигурации не читает. Режим выбирает platform/demo-launcher: ARCHRAG_EAM_MODE = legacy (по умолчанию, null/пусто тоже legacy) | eam-api; для второго обязательны ARCHRAG_EAM_API_URL и ARCHRAG_EAM_API_TOKEN (токен - Docker secret); иное значение режима - IllegalArgumentException (platform/demo-launcher/src/main/java/io/github/unlocker/archrag/demolauncher/LauncherConfig.java:127-139, DemoLauncher.java:138-140) 🟢. В compose по умолчанию стоит eam-api (platform/docker/docker-compose.yml:324), то есть умолчание кода (legacy) и стенда (eam-api) различаются - это сознательно (откат ARCHRAG_EAM_MODE=legacy) 🟢.

Основной поток

Один цикл poller'а (adapter-core) вызывает connector.fetchChanges(cursor, config.pageSize()) (AC/Poller.java:195); для EAM в режиме eam-api это CompositeEamConnector.fetchChanges:

  1. cursor == null → State(snapshot=true, legacyPhase=false, null, null); иначе State.parse(cursor), при IllegalArgumentException → State(false,false,null,null) и WARN (EA/CompositeEamConnector.java:51, 78-85).
  2. Фаза A (eam-api): api.fetchChanges(s.api, limit); страница без nextCursor → IllegalStateException("eam-api answered a page without a cursor"); ответ - те же изменения, новый составной курсор, hasMore=true, snapshotComplete=false; в курсоре фаза переключается на L, когда api вернул hasMore=false (:52-59).
  3. Фаза L (legacy): legacy.fetchChanges(s.legacy, limit); оставляются только TEAM/SERVICE_DEPENDENCY; если legacy.hasMore - страница с hasMore=true и тем же api-курсором; иначе (после проверки snapshot-complete, BR-5) итоговая страница hasMore=false, snapshotComplete = s.snapshot, курсор I;A;… (:60-69).
  4. Внутри api-половины работает EamApiConnector.fetchChanges - подробно в fetch-changes/design.md; HTTP-слой - в eam-api-request/design.md; склейка и курсор - в composite-sync/design.md.
Альтернативные потоки
  • Источник недоступен (429 после повтора, 5xx, IO-ошибка) - SourceUnavailableException(EAM, status, retryAfter); повторы и GaveUp - на Poller.fetch (AC/Poller.java:190-205) 🟢.
  • Любая иная ошибка (401/403/3xx, не-JSON, не-массив, битый ArchObject, битый курсор) - IllegalStateException/IllegalArgumentException без повторов внутри цикла; Poller их не ловит 🟢 (EA/EamApiConnector.java:171, 186, 201, 244).
  • Webhook (fetchById): для EAM eam-api вебхуков не имеет (docs/06-eam-integration.md §«Схема синхронизации»); путь остаётся рабочим для legacy TEAM (ET/CompositeEamConnectorTest.java:151) 🟢.

Риски и пробелы
  • 🟡 Водяной знак сравнивается строго (!isAfter(from)): объект с datetime == watermark, изменённый после снятия водяного знака в ту же секунду/долю, в инкременте не будет прочитан; компенсируется периодическим snapshot (reconcile, 6 ч по умолчанию) (EA/EamApiConnector.java:115, 120). Вопрос Q-2.
  • 🟡 Объект с datetime == null получает EPOCH, поэтому в инкрементальном режиме он всегда считается «уже известным» и прерывает чтение типа (:115-118, 180-181); в graph-слое получает lastSeenAt 1970 (tech-debt Н-17). Q-3.
  • 🟡 Сдвиг страниц при записи во время чтения -mtime может пропустить объекты; план - периодический snapshot (docs/06-eam-integration.md п. 6) 🟢 как допущение, 🟡 как гарантия.
  • 🟢 (реализовано — UNLOCKER-287) Проверка прав сервисной учётки при подключении (200 на три списка, 403/404 на buffers; docs/06-eam-integration.md §«Решения», п. 8): EamApiConnector.verifyAccess(), запускается из DemoLauncher.verifyEamAccess. Q-1.
  • 🟡 Повреждённая eam-api-половина составного курсора (корректный base64, невалидный S|I|W) не восстанавливается: EamApiCursor.parse бросает IllegalArgumentException, CompositeEamConnector её не перехватывает (stateOf ловит только ошибки разбора составного формата) (EA/CompositeEamConnector.java:53, 78-85, EA/EamApiConnector.java:98). Q-4.
  • 🟡 DateTimeParseException из Instant.parse попадает в cause исключения «malformed ArchObject»; её getMessage() содержит разобранный текст, т.е. значение из источника может оказаться в логе стека (EA/EamApiConnector.java:181, 184-186). Комментарий в коде утверждает «причина без значения поля». Q-5.
  • 🟡 SourceConnector.fetchById по Javadoc возвращает DELETE для удалённого объекта (contracts/source-spi/.../SourceConnector.java:26-28), а EamApiConnector на 404 возвращает пусто (EA/EamApiConnector.java:148-150); WebhookHandler строит tombstone только из подписанного уведомления DELETE (AC/WebhookHandler.java:91-106). Для EAM webhook'ов нет, поэтому практического влияния нет.
  • 🟡 EamAdapterContractTest - «контрактный» тест legacy-пути (HttpSourceConnector + StubSources.eam), а не EamApiConnector (ET/EamAdapterContractTest.java:30); фабрика create(config, EamApi, …) в модуле юнит-тестом не покрыта, её проверяют только IT в platform/integration-tests (EamApiSupport.java:31, EamApiProjectionIT, EamKeyMigrationIT).
  • 🟡 Данные о ownerTeam и поля словарей - допущения (docs/06-eam-integration.md п. 9); на коннектор не влияют (он отдаёт attrs как есть).
